7. CONSULTAS FLUX UTILIZADAS EN GRAFANA
========================================================================

7.1 Latencia promedio (avg)
------------------------------------------------------------------------
from(bucket: "jmeter")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "jmeter")
  |> filter(fn: (r) => r._field == "avg")
  |> filter(fn: (r) => r.application == "grupo09-reportes")
  |> aggregateWindow(every: 5s, fn: mean, createEmpty: false)
  |> yield(name: "avg_response_time")

7.2 Percentil 95 (p95)
------------------------------------------------------------------------
from(bucket: "jmeter")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "jmeter" and r._field == "pct95.0")
  |> filter(fn: (r) => r.application == "grupo09-reportes")
  |> aggregateWindow(every: 10s, fn: mean, createEmpty: false)

7.3 Tasa de errores (ko)
------------------------------------------------------------------------
from(bucket: "jmeter")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "jmeter" and r._field == "ko")
  |> filter(fn: (r) => r.application == "grupo09-reportes")
  |> aggregateWindow(every: 30s, fn: mean, createEmpty: false)

7.4 Throughput (req/s)
------------------------------------------------------------------------
from(bucket: "jmeter")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "jmeter" and r._field == "count")
  |> filter(fn: (r) => r.application == "grupo09-reportes")
  |> derivative(unit: 1s, nonNegative: true)
  |> yield(name: "requests_per_second")

7.5 Pivot tabular (formato tabla)
------------------------------------------------------------------------
from(bucket: "jmeter")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "jmeter"
        and r.application == "grupo09-reportes")
  |> pivot(rowKey:["_time"], columnKey: ["_field"], valueColumn: "_value")
  |> keep(columns: ["_time","transaction","avg","max","pct95.0","ko","ok"])

10. RIESGOS IDENTIFICADOS Y MITIGACIÓN
========================================================================

Riesgo 1: Saturación de la base de datos por carga concurrente
Mitigación: carga gradual (ramp-up), límite de usuarios y duración.
Criterio de detención: bloqueos en BD → abortar.

Riesgo 2: Tasa de errores superior al 1 %
Mitigación: monitoreo en Grafana con alerta automática.
Criterio de detención: errores > 5 % → detener prueba.

Riesgo 3: Latencia p95 superior a 800 ms
Mitigación: reducir usuarios o abortar según umbral de Grafana.
Criterio de detención: p95 > 2000 ms → abortar.

Riesgo 4: Exposición del token de InfluxDB Cloud
Mitigación: rotar token, externalizar con user.properties o variables
de entorno, no subir el JMX con el token real al repositorio.

Riesgo 5: Ambiente no controlado
Mitigación: usar sandbox, datos sintéticos, nunca producción.
